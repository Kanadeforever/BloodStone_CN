# NPCSubtitles 过场事件与字幕生命周期

## 实机现象与目标

v0.1e-log5 三行独立 NPC 字幕已通过用户实机验收，但过场画面开始时旧字幕继续显示。需要在过场开始前后及时清掉三个活动位置、全部等待项和去重记录，并让新的 NPC 对话在过场结束后恢复。不能用缩短所有字幕持续时间代替过场识别，也不能以屏幕是否变黑、分辨率变化或字幕文本内容来猜测过场。

## 静态依据

适用游戏原始 PE 指纹：`TimeDateStamp=0x4CA36144`，`SizeOfImage=0x010CC000`。原始明文 EXE 的事件名称表有 `CutSceneStart` / `CutSceneEnd`，哈希式消息类型分别为 `0xA2193087` / `0xA2193088`。游戏实际在 `0x00B4860D` 与 `0x00B48654` 等位置准备消息并调用 `0x00E46E70` 派发；本版本不需要覆盖每个发送点。

`0x00E46E70` 入口机器码 `56 8B F1 E8 68 10 6A FF` 表示 `push esi; mov esi,ecx; call 0x004E7EE0`。事件消息指针在调用入口栈 `[esp+4]`，首个 32 位字段是类型 ID。安装前必须完整校验机器码及 CALL 目标。不满足条件时放弃这项辅助 Hook，保留已有 NPC 字幕链。

## 运行时处理

安装时通过 Win32 `VirtualAlloc` 分配短执行跳板，把原始 8 字节搬入其中，修正 CALL 相对位移，并接续 JMP 返回 `0x00E46E78`。原始入口只改 8 字节，跳到无 C++ 框架开销的 x86 裸函数；非两个目标事件直接跳回原始跳板。两个目标事件在完整保存与恢复寄存器、EFLAGS 后进入回调。

收到开始事件时，写入原子状态并在字幕短锁中调用 `subtitle_queue::Clear`；等待队列不能在下一帧恢复旧字幕。过场期间跳过 EndScene 字幕绘制和新消息入队；收到结束事件后清除状态，使新 NPC 对话正常显示。为覆盖未发送本事件的部分剧情场景，原生对白 `+0x1C=0` 接管时也清空旧 NPC 字幕；该辅助规则只能在剧情对白出现时起效。

## 验证范围及风险

静态分析确认了事件名称、ID、真实发送指令和派发入口，不代表所有过场都由它触发。该事件总线用于其他游戏消息，虽然非过场分支只有几条指令，但新增 Hook 仍需实机复测手柄图标、游戏性能及场景切换后的恢复情况。仅在 `--log` 模式记录 `CUTSCENE_START_QUEUE_CLEARED`、`CUTSCENE_END_QUEUE_RESUMED` 等信息。

测试：在 NPC 对话仍显示时进入实时过场与视频过场、跳过过场与等待自然结束，再回到普通场景触发 NPC 台词。若其中某类场景不发送原生事件，必须根据日志单独补充识别路径，不能将当前结果称为全面覆盖。

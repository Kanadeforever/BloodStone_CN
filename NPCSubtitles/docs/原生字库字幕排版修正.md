# v0.1e 原生字库字幕排版与黑底修复

> **最终实机结论**：本版已由用户确认黑底消失，中英文和数字同高，从 640×480 至 4K 自动缩放良好。下文“未验证项”为初次编译候选时的历史记录。当前维护候选为 v0.1e-log5，保持字形和透明度算法，但把同屏对白改为最多三条独立消息；详见《三行字幕调度与回归验证.md》。

## 一、用户截图与原始问题

v0.1d 实机截图显示同一字幕内中文、英文和数字显著高低不一致；字形下面有按字符切开的黑色矩形。此前 `Configure()` 的 `D3DRS_SRCBLEND=SRCALPHA(5)`、`DESTBLEND=INVSRCALPHA(6)` 默认假设字形纹理含透明背景；而原生图块的黑色 RGB 像素并不能保证 alpha 为零。绘制时这些像素也参与覆盖，形成黑块。字幕此前使用 `viewport.height / 480 * 0.56`，导致高分辨率下按比例放大。

## 二、最终绘制策略

仍然使用原版 `Glyph` 返回的 D3D9 纹理、UV、advance，不生成 BFA、Windows 字体或单独纹理。保留 D3D9 StateBlock/Reset/EndScene。

- 主体：`SRCBLEND=ONE(2)`，`DESTBLEND=INVSRCCOLOR(4)`。将黑色背景的 RGB=0 转换成“目的像素保留”，白色笔画转为覆盖。注意这不是通用任意彩色图片合成，只针对当前白色字形的黑底图块。
- 阴影：`SRCBLEND=ZERO(1)`，`DESTBLEND=INVSRCCOLOR(4)`，使用灰色顶点与原始纹理亮度相乘，笔画处略暗化背景；黑色底纹不会生成矩形。
- 主体与阴影在相同 StateBlock 下分两次提交，仍在游戏原始 `EndScene` 之前执行，绘制完恢复 D3D9 状态。
- 按同句有效 CJK 字形高度求平均，将显著更高的 ASCII 字符压缩到中文高度约 105% 以内，不放大小字形；所有字形按共同基线底边对齐。
- 480p 参考缩放因子 `0.43`，随视口高度每增加 480 像素仅增加 `0.24`，限制在 `0.30～1.40`。该线性幅度的增长使**相对字号**随高分辨率下降；每帧读取当前 viewport，无需 INI 或重启。
- 最多显示三行，最大字幕宽度为当前 viewport 的 76%，每行单独居中，行高为实际最大字形高度的 1.20 倍。

## 三、未验证项

修正已经离线编译，但需要 Windows 游戏实机判定实际 GPU 混合结果。尤其要观察高亮背景下白色字形可读性、阴影强度、不同中文原生字体面对 Latin 高度的影响和分辨率切换后的字号变化。若游戏原生字形纹理带特殊颜色，亮度混合可能需要针对纹理格式继续校准。

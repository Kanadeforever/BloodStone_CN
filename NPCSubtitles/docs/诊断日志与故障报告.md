# NPCSubtitles：故障报告与按需日志

## 启用与文件位置

直接启动 `Bond.exe` 不创建、不更新，也不删除任何 NPCSubtitles 日志。使用独立命令行参数 `Bond.exe --log` 时，才在 `NPCSubtitles.asi` 所在目录写入：

- `NPCSubtitles_boot.log`：DLL 附加及工作线程创建最后检查点。
- `NPCSubtitles_phase.log`：当前初始化执行到的最后阶段。
- `NPCSubtitles.log`：带本地毫秒时间、线程号、哈希、中文预览、Win32/D3D9 状态的详细故障事件。

已有旧日志不会被普通启动清除。命令行要求完整匹配 `--log`，不会把 `--logger`、`--log=1` 或文件路径里的字符串误当成启用开关。其他插件只有自己也主动识别 `--log` 才会开启日志。

## 诊断事件

| 标记 | 意义 |
|---|---|
| `GAME_SIGNATURE_OK` | 游戏 PE 版本指纹匹配 |
| `LOC_FILE_SCANNED` / `LOC_FILE_ACCEPTED` / `LOC_FILE_SKIPPED` | 逐文件中文 LOC 解析结果 |
| `NATIVE_EVENT_ROUTE_OFFSET=28` | 使用原始事件 `+0x1C` 字节判断剧情／NPC 路由 |
| `ORIGINAL_DIALOGUE_EVENT` | 同一 Dialogue Hook 采集的原始事件与派生字段 |
| `NPC_NATIVE_EVENT_SUPPRESSED` | 游戏事件属于原生字幕通路，插件没有重复入队 |
| `NPC_EVENT_ROUTE_UNKNOWN` | 事件指针或标志不可靠，本次安全跳过 |
| `NPC_DIALOGUE_INDEX_HIT` / `MISS` / `FILTERED_HASH` / `AMBIGUOUS_HASH` | LOC 内容对应结果，分别区分存在、缺失、硬键名过滤和重复歧义 |
| `NPC_SUBTITLE_QUEUE_HASH` | 确认 NPC 台词进入外挂显示队列，附中文预览 |
| `D3D9_*` / `NPC_DRAW_SUBMITTED` / `NATIVE_GLYPH_CAPTURED` | 图形 Hook、绘制和原生字形资源捕获情况 |
| `STATS native_events_suppressed/draw_calls` | 原生字幕过滤数量及绘制调用统计 |
| `STATS route_probe_events/unknown` | 实际诊断事件数与未能分类数 |

这些记录只能说明执行路径与 API 调用，不能替代实际游戏画面证据。

## 运行性能和兼容性

默认不调用文件日志或调试输出。`--log` 使用同步写盘，每条事件输出本地时间与线程号，因此可能引入额外开销；EndScene 不逐帧写日志，而按约 30 秒汇总。正常游玩不建议使用 `--log`。

当前插件**不再挂接 `0x0093039D` 原生 UI CALL**。历史 v0.1e-log3 中的 `ORIGINAL_UI_SUBMIT_PROBE_READY`、`ORIGINAL_NATIVE_UI_SUBMIT_CALL` 仅适用于那次诊断，不能在本版寻找。

提交崩溃报告时同时附 boot、phase 和普通日志。提交字幕问题时还需描述关卡、原生 UI 是否有字幕、对应声音与必要截图。日志包含实际安装路径和少量中文台词，公开前可手动检查隐私信息；插件不会自动上传数据。若日志模式影响手柄图标或性能，优先比较正常启动和 `--log` 启动的差别。


## 三行队列新增诊断（v0.1e-log5）

默认启动 `Bond.exe` 不创建或修改日志。仅 `Bond.exe --log`：`NPC_SUBTITLE_QUEUE_HASH` 表示哈希匹配且消息被接受（立即显示或等待）；`NPC_SUBTITLE_DEFERRED visible/waiting` 表示三条活动字幕已满，待显示消息进入 FIFO 队列；`NPC_SUBTITLE_QUEUE_FULL` 表示十六个等待项也已占满，此新消息没有覆盖旧消息，但未能入队。周期汇总 `STATS deferred/full` 分别累计等待与满载拒绝次数，`STATS max_simultaneous_dialogues` 记录三个活动槽位曾同时使用的最大数。

如报告“多条对话被顶掉”，请用 `--log` 连续触发几句环境对白，保留对应的 `NPC_SUBTITLE_QUEUE_HASH`、`NPC_SUBTITLE_DEFERRED`、`NPC_SUBTITLE_QUEUE_FULL` 及周期统计。请区分“同时显示不够三行”“等待文本很晚才显示”和“等待队列已满”，三者分别对应排版、时序与容量问题。

## 历史过场事件诊断（v0.1e-log6）

`CUTSCENE_NATIVE_EVENTS_HOOK_READY` 表示针对明文 Bond.exe 的原生游戏事件派发入口安装了过场识别跳板。`CUTSCENE_NATIVE_EVENTS_HOOK_UNAVAILABLE` 表示入口已被修改、版本不匹配或无法安装，NPC 普通字幕仍可工作，但无法保证过场开始时立即隐藏。

`CUTSCENE_START_QUEUE_CLEARED` 表示收到游戏原生过场启动消息并清空了可见与等待队列；`CUTSCENE_END_QUEUE_RESUMED` 表示收到过场结束消息并允许后续 NPC 字幕重新入队。`NATIVE_DIALOGUE_QUEUE_CLEARED` 表示原生剧情对白接管时清除了剩余的环境 NPC 字幕。`STATS cutscene_start/end` 与 `STATS cutscene_clear/native_clear` 分别汇总次数。

所有这些事件只在 `Bond.exe --log` 模式写盘，普通游玩依然完全禁用日志。若某个过场仍残留字幕，提交该过场开始前后的日志以及关卡名称和进入方式，以判断是否缺少游戏原生过场通知。


## v0.1e-log7 白名单诊断

本版仍由完整命令行开关 `--log` 控制全部诊断日志。`CUTSCENE_START_QUEUE_CLEARED` 已改为 `CUTSCENE_START_QUEUE_BEFORE` 和 `CUTSCENE_START_QUEUE_RETAINED`，分别表示开始过场前的队列数量、清理普通 NPC 以后保留的白名单数量。

- `CUTSCENE_ALLOWLIST_EMBEDDED=10`：内置规则表已加载。
- `CUTSCENE_ALLOWLIST_LOC_MISSING_OR_AMBIGUOUS`：某条白名单没有找到唯一匹配的有效译文；需核查现用中文 LOC。
- `CUTSCENE_ALLOWLIST_QUEUED`：该条符合白名单并在正常阶段入队。
- `CUTSCENE_ALLOWLIST_QUEUED_IN_SCENE`：该条在过场内进入字幕队列。
- `CUTSCENE_ALLOWLIST_INDEX_MISS`：对白事件出现，但没找到其资源记录。
- `STATS allowlist_accepted/during_cutscene`：白名单累计入队、过场内入队次数。
- `STATS allowlist_waited/index_missing`：等待队列与索引缺失计数。

诊断仅说明 Hook 捕获和字幕入队，无法单独证明画面可见；若仍缺某句，需确认是否完全没有对应事件触发，还是被游戏场景的渲染条件阻断。保留手柄图标、帧率测试记录。历史 log6 标记仅用于解释旧日志，当前 ASI 可能不再输出同名项目。

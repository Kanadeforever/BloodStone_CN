# M1 原生 NPC 字幕：启动崩溃根因调查

## 当前已知事实与证据等级

2026-10-10 用户实机报告：独立交叉编译的 `NPCSubtitles.asi v0.1` 与已经成功的 NativeLooseAssets v0.9 同时安装时，游戏进程内存约 3 MB 即崩溃；插件日志缺失。该结果足以否定 v0.1 编译候选的可用性，但不足以确定哪个 Hook 或哪个模块导致异常。

旧 ASI 经静态 PE 检查：`SizeOfImage = 0x0034C000`，这是 DLL 的**虚拟映像大小**，不等于 Windows 任务管理器显示的进程工作集；不能把两个“约 3 MB”的数字直接当作因果关系。约 4,200 条 NPC 文本采用 `Entry[4200]` 常驻大数组是可确认的多余装载成本。

旧版 D3D9 初始化流程会主动创建临时 Direct3D9 接口并修改 CreateDevice 虚表，之后释放临时对象。如果第三方 D3D9 包装器为每个对象单独维护虚表，这种顺序可能使已保存的虚表位置不再有效。这是风险推断，而不是本次崩溃的既定根因。

`NPCSubtitles.log` 仅在后台线程成功获取自身路径并创建文件后才出现。无日志的潜在原因包括：DLL 未被装载、入口前的装载失败、DllMain 异常、后台线程尚未执行即发生异常、路径无法写入；因此**不能仅凭没有日志推定为 Hook 崩溃**。

## 当前做出的可逆修正

- 正式文件名保留 `NPCSubtitles.asi`，功能版本写为 `v0.1a`，不扩大 NPC 事件入口范围。
- 文本表从 DLL 的静态数据段迁移到 `VirtualAlloc`，游戏版本指纹通过之后才申请；新功能 ASI PE `SizeOfImage` 约 196 KiB，真实内存分配与其分开记录。
- 取消创建临时 Direct3D9 接口和修改其虚表的启动路径，设备 Hook 只能来源于游戏真正创建的 Direct3D9 接口。
- 新增 `GAME_SIGNATURE_OK` 和 `NPC_INDEX_ALLOCATED` 分阶段日志。
- 单独编译无 Hook 的启动诊断 ASI，同样叫 `NPCSubtitles.asi`，仅在 DllMain 写 `NPCSubtitles_boot.log`。它不会尝试绘制 NPC 字幕，与功能候选只能二选一。
- 保留 NativeLooseAssets v0.9 和现有 `BSCNContents` 不变，原版 EXE、PAK 与字体资源不修改。

## 当前可验证结论

- 两份候选均为实际编译、链接得到的 Win32/x86 PE32 DLL。
- 活动源码及 ABI 合同、PE 检验、无 Hook 启动诊断边界已通过自动化测试。
- 静态逆向中的 NPC Dialogue 和字体资源原始 CALL 地址未改变。
- **没有用户的下一次实机记录前，不能声称 v0.1a 修复了崩溃，也不能恢复 NPC 运行时已验收的标记。**

## 下一步诊断分支

若启动诊断版也崩溃，优先查 ASI Loader、内核导入和 DllMain 装载上下文。如果诊断版正常而功能版崩溃，根据功能日志最后一条记录，分别调查 `VirtualAlloc/LOC`、原生字体 Hook、Dialogue Hook、D3D9 IAT/虚表 Hook。若功能版稳定却无字幕，再单独调查设备创建时序和 Unicode 字形捕获。禁止以重复尝试调文字坐标来掩盖启动异常。

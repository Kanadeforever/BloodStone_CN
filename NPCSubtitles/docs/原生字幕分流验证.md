# NPC 原生字幕分流：实机证据、正式判定及剩余风险

## 已确认的游戏代码

目标 Bond.exe 的 PE 时间戳为 `0x4CA36144`，映像尺寸为 `0x010CC000`；目前插件只支持该游戏指纹。

- `0x0093A26C`：`cmp byte ptr [edi+0x1D],0`，派生出对白对象 `+0x79`。
- `0x0093A282`：`cmp byte ptr [edi+0x1C],0`，派生出对白对象 `+0x7A`。
- `0x0093A2A1`：`call 0x00F12820`，NPCSubtitles 已实机验证的文本获取调用点，位于原生字幕分流之前。
- `0x009302D5`：依据内部 `+0x7A` 决定是否经过游戏原生 UI 文本提交分支。
- `0x0093039D`：原生 UI 提交 CALL，历史诊断版曾临时 Hook；**当前版绝不 Hook**。

原始事件的 `+0x1C=0` 对应 `+0x7A=1`，原生提交分支允许执行；`+0x1C=1` 对应 `+0x7A=0`，该分支不执行。`+0x1D` 是独立标志，不应代替 `+0x1C`。

## 本版分流与性能边界

新插件仅在原本已存在的 `0x0093A2A1` Dialogue Hook 中读取事件结构的一个字节 `+0x1C`。原生字幕类别时直接返回，不做 LOC 查找、纹理绘制入队或复杂语义签名计算。对无法安全读取的值一律不入队；`--log` 才保留详细事件字段。

v0.1e-log3 的新增 UI CALL 探针，在用户实机测试中同时出现手柄图标 MOD 受影响和游戏运行略有下降。该探针仅捕获少量 UI 提交，**没有证据证明这两个问题一定由它直接引起**；`--log` 同步写盘、调试输出及其他插件 Hook 的顺序都可能参与。当前版完整移除额外 UI Hook 和昂贵语义签名，待用户以相同运行条件再次实机对照。

## 日志及回退

`Bond.exe` 默认不写日志，`Bond.exe --log` 创建三份独立日志。`ORIGINAL_DIALOGUE_EVENT` 仍可观察事件标志；`NPC_NATIVE_EVENT_SUPPRESSED` 明确标识原生通路被禁止入队；`NPC_EVENT_ROUTE_UNKNOWN` 表示无法可靠分类；`NPC_SUBTITLE_QUEUE_HASH` 标识已经入队。

当前版没有 `ORIGINAL_UI_SUBMIT_PROBE_READY`、`ORIGINAL_NATIVE_UI_SUBMIT_CALL`，不需要 TSV 或 INI。若不能正常运行，可只换回已实机通过的原版 v0.1e。该分流行为是**新的待验收代码**，不能因为静态测试通过就宣称字幕完全不再重复。

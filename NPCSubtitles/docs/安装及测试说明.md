# NPCSubtitles v0.1e-log6：安装与实机验证

## 一、安装

本发行包已包含真实编译的 Win32/x86 `release/NPCSubtitles.asi`。在已安装 BloodStoneCN/NativeLooseAssets 的游戏环境中，用此文件替换原有 `NPCSubtitles.asi` 即可。插件与当前使用的 `BSCNContents\loc`、`BSCNContents\fonts` 保持在同一 ASI 加载目录，不假定目录一定叫 `plugins` 或 `scripts`。

**不需要** `NPCSubtitlesSemanticRoutes.tsv`、`NPCSubtitles.ini`、BFA 或 BLI。不要修改原版 `Bond.exe`、PAK、主汉化或手柄图标 MOD。请不要同时放置多个版本的同名 NPC ASI。

## 二、对白类型及字幕分流

游戏原始对白事件 `+0x1C=1` 时，NPCSubtitles 才尝试按 LOC 哈希读取中文并入队；`+0x1C=0` 时由游戏自身处理原生剧情字幕，外挂不重复绘制。读取无效则保持静默。这个机制已经在 v0.1e-log4 通过用户实机测试，且旧版侵入式原生 UI 调试 Hook 已被移除。

**本插件不负责 BattleChatter 战斗喊话**。此前 v0.1f 虽然触发相关 Hook，却未能识别 VoiceSet，因此不能承诺“敌人发现玩家”等战斗台词会有中文字幕。

## 三、三行显示及排队

- 屏幕同时最多显示三条独立 NPC 对话；每条保留自己的显示时间与文本。
- 只有一条时保留最多三行的自动换行，两条时最少各一行，三条时各占一行。
- 第四条及以后进入 FIFO 等待队列，最多等待十六条；有空行时自动依次显示，不再立即覆盖正在显示的字幕。
- 同一哈希短时间重复触发仍会去重。极端情况下十六个等待位置全部用满，新对白保持静默并在调试日志中记录队列满载。
- 如果同屏出现多条特别长的文本，剩余行会根据当前分辨率自动水平缩放，确保不会越出屏幕。极端长度可能导致字号变小，仍需实机验证。

## 四、进入过场后的字幕清空

游戏原生 `CutSceneStart` 消息（`0xA2193087`）到达后，插件清空正在显示的至多三条字幕和全部等待队列。过场期间不再显示或补入旧 NPC 台词；`CutSceneEnd`（`0xA2193088`）到达后恢复 NPC 入队。原生剧情对白接管事件也会清掉剩余环境对白，作为部分过场没有立即发送启动消息时的辅助处理。

这项修改**需要本次实机确认**，并不等于所有过场类型都被覆盖。

## 五、如何测试及回退

先正常启动 `Bond.exe`（不带 `--log`），在字幕尚显示时进入过场，确认字幕与等待队列立即清空；过场结束或跳过后检查 NPC 字幕恢复。然后复测三行并发、手柄图标 MOD、FPS、透明背景、640×480 至 4K 自适应和剧情字幕分流。

需要提交故障报告时用 `Bond.exe --log`。`NPCSubtitles.log`、`NPCSubtitles_boot.log`、`NPCSubtitles_phase.log` 仅在这种调试启动方式下创建或更新。新日志项目：`NPC_SUBTITLE_DEFERRED`、`NPC_SUBTITLE_QUEUE_FULL`、`STATS deferred/full`、`STATS max_simultaneous_dialogues`、`CUTSCENE_NATIVE_EVENTS_HOOK_READY`、`CUTSCENE_START_QUEUE_CLEARED`、`CUTSCENE_END_QUEUE_RESUMED` 与 `NATIVE_DIALOGUE_QUEUE_CLEARED`。其他原有的 LOC、游戏版本、Hook、字形、D3D9 诊断记录保留。

如果过场后字幕不再恢复、游戏崩溃、手柄图标模组受影响或帧率下降，请恢复 **已实机通过的 v0.1e-log5** `NPCSubtitles.asi`。v0.1e-log6 的新增原生过场事件监听尚未通过 Windows 实机验收，不得提前封版。

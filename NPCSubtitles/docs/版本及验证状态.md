# NPCSubtitles v0.1e-log6：版本与验证状态

## 项目目标

本项目只给《007 Blood Stone》自身不会绘制字幕的 NPC 环境对白补充中文，不改变游戏原生剧情字幕、不加入未经验证的 BattleChatter 战斗喊话。使用原生中文 LOC、游戏已载入的 EUR 中文字体纹理和原有 D3D9 设备，所有路径相对 ASI 所在目录。

## 已冻结的三行调度机制

前一稳定版仅有一份活动字幕文本，因此同时触发两句或三句环境对白时，后一条会覆盖前一条，虽然文字本身支持最多三行自动换行。本版把显示数据改为最多三个独立活动槽位，另有十六条先进先出等待记录。每条字幕有独立开始时间和结束时间；满屏时新对白排队，不立即覆盖任何已显示对白；有活动槽位到期后才把最早等待项补上，并从真正显示时开始计算时间。

**画面始终最多三行**：三条对话各保留一行；两条同时显示时，剩余一行可以用于长句换行；只有一条时最多占三行。行高、透明字形、字体、高分辨率缩放和游戏原生 UI 事件分流均沿用已经实机通过的实现。行预算不足的长句会在剩余行内水平缩放保证内容不被移出视口；极长文本可能显得偏小，需由实机确认可读性。

等待队列上限十六条；如果极端情况下容量耗尽，新入队的对白会被拒绝而不会覆盖已显示/已排队的记录，`--log` 模式记录 `NPC_SUBTITLE_QUEUE_FULL`。连续大量对白可能造成等待文本晚于语音播放，属于当前有限缓冲与三行限制之间的已知权衡。

## 新增过场切换处理

BattleChatter（敌人发现玩家、搜索、交火的战斗喊话）没有完整字幕支持。之前 0.1f 捕获播放回调和槽位，但 VoiceSet 始终无法确认，已从稳定版排除。部分战斗场景的普通脚本对白可能经过现有 NPC 入口，但这不等于战斗喊话覆盖完成。

v0.1e-log5 的三行调度已由用户实机确认。v0.1e-log6 使用游戏原生 `CutSceneStart=0xA2193087` 和 `CutSceneEnd=0xA2193088` 消息，在过场开始时清空可见字幕和等待队列，并停止绘制及入队；过场结束后恢复。还保留游戏原生剧情对白接管时清空旧 NPC 文本的辅助机制。

本轮新增事件监听尚未完成 Windows 实机验证，不能保证所有预录视频或特殊镜头转换都发出上述消息。**如有手柄图标 MOD、帧率或过场后 NPC 字幕回归，立即恢复 v0.1e-log5。**

## 使用与验证

无需 TSV 或 INI，只替换 `release/NPCSubtitles.asi`。正常 `Bond.exe` 不写日志；`Bond.exe --log` 创建三份诊断日志并记录对白哈希、分流、排队和丢弃情况。

建议在过场开始前让 NPC 字幕仍在显示，检查开始过场时是否立即清空；跳过或自然结束过场后继续触发 NPC 对话，确认字幕恢复。再复测手柄图标 MOD、三行并发、原生剧情字幕分流和帧率。

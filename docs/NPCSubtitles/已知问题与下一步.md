# NPCSubtitles 0.2.2 已知问题与下一步

## 0.1 已确认成功

用户实机确认 0.1 NPC 字幕能够正常显示，整体效果“超出预期”。同时确认：

1. 双行间距偏大；
2. 字幕整体位置略低；
3. 改变分辨率后字幕消失。

## 0.2 实机回归：启动后完全不显示

0.2 首次实机日志显示：

```text
NPC_DIALOGUE_INDEX_READY files=21/22 records=1314
NPC_SUBTITLE_D3D9_IAT_HOOK_OK
NPC_DIALOGUE_HOOK_OK
NPC_DIALOGUE_EVENT ... index=HIT allowed=1
NPC_SUBTITLE_QUEUE ...
```

但整个日志完全没有：

```text
NPC_SUBTITLE_CREATE_DEVICE_HOOK_OK
NPC_SUBTITLE_RESET_HOOK_OK
NPC_SUBTITLE_ENDSCENE_HOOK_OK
BFA_GPU_OK
```

因此 0.2 的失败不是 Dialogue、LOC、过滤、queue 或 BFA CPU 解析，而是 D3D9 绘制 Hook 没有接到真实 Device。

### 根因

Worker 初始化顺序会先解析全部 script_dialogue LOC，再安装 `Direct3DCreate9` IAT Hook。该次日志中从插件启动到 IAT Hook 安装约经过 464 ms。Bond 已经在这段时间内创建了 D3D9 Device，故后装 IAT Hook 无法倒追已经发生的 `Direct3DCreate9/CreateDevice`。

这说明 0.1 的 IAT-only 方案存在启动时序竞态；0.1 成功时只是恰好赶上了 D3D 创建时机。

## 0.2.1 修复

保留原 IAT chain，同时新增 `BootstrapDeviceHooks()`：

1. 使用 IAT Hook 时观察到的 previous `Direct3DCreate9` 创建临时 `IDirect3D9`；
2. 从其 vtable 安装 `IDirect3D9::CreateDevice [16]` chain；
3. 创建隐藏的 8x8 HAL 临时 D3D9 Device；
4. 从临时 Device 的共享 vtable 安装 `Reset [16]` 与 `EndScene [42]` chain；
5. 立即释放临时 Device/窗口；
6. 真实 Bond Device 即使早已创建，只要使用同一 D3D9 实现的共享 vtable，也会进入新的 EndScene/Reset Hook。

临时 Device **不创建 BFA GPU 纹理**；首次真实 Bond EndScene/字幕绘制时才针对真实 Device 创建资源。

新增首个 EndScene 存活日志：

```text
NPC_SUBTITLE_ENDSCENE_ACTIVE viewport=...
```

## 0.2.1 首轮实机必须确认

NPC_SUBTITLE_D3D9_IAT_HOOK_OK

第一次中文字幕实际绘制时应看到：

```text

```

如果这些都成立，再继续测试分辨率切换后的 Reset 生命周期。

## 仍待实机确认

- 0.2.1 bootstrap 在 Bond 实机环境是否能稳定获取与真实 Device 共享的 vtable；
- 0.2 原本新增的 Reset Hook 是否覆盖实际分辨率切换路径；
- `BaseY=0.120` 与 `LineSpacing=0.82` 是否达到最终视觉目标；
- 英文 fallback Reset 后的原生字体重新捕获；
- `geneva_script_dialogue.loc` 当前仍单文件解析失败，但索引 21/22 可用；该问题与本次完全不显示无关，暂不作为阻塞。

## 冻结结论

- 唯一正式 Dialogue Hook 仍为 `0x0093A2A1 -> 0x00F12820`；
- 不恢复 `SubmitText 0x00E85900` NPC UI 路线；
- 不恢复另外两处重复 Dialogue callsite；
- 战斗字幕继续封存；
- BFA/BLI/LOC 完全外置；
- 英文 fallback 不内置完整英文字幕表。

# NPCSubtitles 0.2.2 D3D9InteropSafe 技术说明

## 核心触发链

```text
Bond.exe 0x0093A2A1
  call 0x00F12820(dialogue_id)
        ↓
NPCSubtitles HookLookup
        ↓
中文：script_dialogue LOC index → BFA D3D9 自绘
英文：原函数返回对象 → 英文运行时探测 → 游戏原生字体 D3D9 自绘
```

生产环境仍只 Hook 一处 Dialogue callsite，不恢复 `SubmitText 0x00E85900` NPC 路线。

## D3D9 Hook 链

```text
Bond.exe Direct3DCreate9 IAT
        ↓
IDirect3D9::CreateDevice [16]
        ↓
IDirect3DDevice9::Reset [16]
IDirect3DDevice9::EndScene [42]
```

0.2.1 仍保留上面的正常 future-call 路线，但不再假定插件一定能赶在游戏创建 Device 前安装。

### 0.2.1 late-install bootstrap

0.2 实机日志证明 IAT Hook 安装时游戏 Device 已经存在，因此新增：

```text
previous Direct3DCreate9
        ↓
临时 IDirect3D9
        ↓
安装 CreateDevice vtable chain
        ↓
隐藏 8x8 HAL 临时 Device
        ↓
安装 Reset / EndScene 共享 vtable chain
        ↓
释放临时 Device
```

临时 Device 只用于取得 D3D9 vtable，不承载字幕资源。`HookDevice(dev,false)` 明确禁止在 bootstrap Device 上创建 BFA GPU Texture。第一次真实 Bond EndScene 到达时才按真实 Device 创建纹理。

新增诊断：

```text
NPC_SUBTITLE_D3D9_BOOTSTRAP_BEGIN
NPC_SUBTITLE_CREATE_DEVICE_HOOK_OK source=bootstrap
NPC_SUBTITLE_D3D9_BOOTSTRAP_OK
NPC_SUBTITLE_ENDSCENE_ACTIVE viewport=...
```

所有 Hook 继续采用 observed previous pointer/target 链式调用，不把 BloodstoneCN 或第三方 wrapper 假设为“原始函数”。

## 0.2 首次实机暴露的启动竞态

0.2 日志中 Dialogue/LOC/queue 全部正常，但完全不存在 CreateDevice/EndScene/BFA_GPU 日志。结合初始化顺序，确认插件在解析 22 个 LOC 后才安装 IAT Hook，约 464 ms 的窗口足以让 Bond 提前完成 D3D9 Device 创建。

因此 0.1 的 IAT-only 路线并非确定可靠；0.2.1 的 bootstrap 是对这一架构缺口的正式修复。

## 为什么 0.1 改分辨率后会丢字幕

0.1 为减少共存风险，明确不 Hook Reset。实机已经证明这个假设不成立：游戏改变分辨率后会进入 D3D9 设备/资源生命周期变化，而 NPCSubtitles 没有收到失效与重建通知。

因此 0.2 将“分辨率变化”正式纳入渲染器生命周期：

### Reset 前

中文模式：

```text
FontAtlas::InvalidateGpuTexture()
```

只释放 GPU 侧 `IDirect3DTexture9*`，保留已经解析好的 BFA CPU 像素和 glyph metrics。

英文模式：

```text
NativeFontCapture::InvalidateGpuResources()
```

清空捕获到的游戏原生纹理裸指针，避免 Reset 后继续访问旧 D3D 资源。

### Reset 成功后

中文模式立即：

```text
FontAtlas::EnsureTexture(new/current device)
```

重新创建 `D3DPOOL_MANAGED` BFA 纹理并上传 CPU atlas。

英文模式不主动调用未知游戏资源构造器；等待已经存在的 NativeGlyph/resource Hook 重新捕获游戏自己的有效纹理，避免为修 Reset 引入新的游戏内部调用风险。

## Reset 诊断日志

```text
NPC_SUBTITLE_RESET_HOOK_OK
NPC_SUBTITLE_DEVICE_RESET_BEGIN request=1920x1080 windowed=...
NPC_SUBTITLE_DEVICE_RESET_FAILED hr=0x........
NPC_SUBTITLE_DEVICE_RESET_OK mode=CHINESE_BSCN chinese_texture=1 viewport=1920x1080
NPC_SUBTITLE_POST_RESET_DRAW_OK viewport=1920x1080
```

这些日志是 0.2 之后判断分辨率问题的正式证据，不再只依靠“切完后是否可见”的现象猜测。

## 布局调整

0.1 默认：

```text
BaseY=0.145
双行 advance 主要来自 atlas line_height
```

0.2 默认：

```text
BaseY=0.120
LineSpacing=0.82
```

中文和英文的双行 advance 都改为：

- 优先使用较紧的 `LineSpacing` nominal advance；
- 同时以“上一行实际可见 glyph 高度 + 约 1 个 720p 基准像素”为下限；
- 因此不会因为把 `LineSpacing` 调得太小而直接重叠。

多个并发字幕事件之间的固定垂直步进也从 0.1 的宽松值收紧，但不改变字幕捕获、去重和持续时间逻辑。

## 英文原生字体地址

仍为：

```text
0x011A02D8 NativeGlyph lookup slot
0x00E42C21 resource resolve CALL
font + 0x12C resource handle
resource + 0x08 IDirect3DTexture9*
```

本轮不改变英文正文扫描算法和字体选择策略，只补 Reset 后的 GPU 指针生命周期。

## 0.2.2：Interop-Safe Bootstrap

### 0.2.1 的互操作事故

实机同时加载 `BloodstoneCN.asi` 与 `NPCSubtitles 0.2.1` 时，两份日志出现了同一线程、同一时间点的确定证据：

```text
NPCSubtitles:
01:41:46.814 NPC_SUBTITLE_CREATE_DEVICE_HOOK_OK source=bootstrap

BloodstoneCN:
01:41:46.814 D3D9 CreateDevice hook installed
01:41:47.444 BFA_GPU_OK texture=07E13340
01:41:47.444 FONT_GATE_READY localization_output=ENABLED
```

而 NPCSubtitles 的 8×8 临时 Device 正是在这段 bootstrap 中创建。

这证明 0.2.1 的 `previous_d3d9_` 实际可以是 BloodstoneCN 已安装的 IAT chain；`previous_create_` 也可以成为 BloodstoneCN 的 CreateDevice chain。于是 NPCSubtitles 为恢复 EndScene 而创建的 dummy Device，反过来触发了 BloodstoneCN 的真实字体初始化。

主汉化随后拿着建立在 dummy Device 上的 BFA GPU 资源继续运行，表现为版权页/中文 UI 字形纹理严重错乱。该问题与 LOC 文本、M2F1、TextCoverage、NPC 字幕内容本身无关。

### 0.2.2 规则

bootstrap 必须满足以下互操作不变量：

```text
NPC 临时 Device
不得经过 BloodstoneCN / 其它 ASI 的 Direct3DCreate9 IAT chain
不得经过 BloodstoneCN / 其它 ASI 的 IDirect3D9::CreateDevice hook
不得让其它插件把 dummy Device 识别为 Bond 的真实 Device
```

实现：

```text
GetModuleHandleW("d3d9.dll")
  ↓
GetProcAddress("Direct3DCreate9")      # 绕过 Bond.exe IAT chain
  ↓
raw IDirect3D9
  ↓
检查 vtable[16] CreateDevice owner
  ├─ owner == d3d9.dll → 允许 raw CreateDevice 创建 8×8 dummy
  └─ owner != d3d9.dll → SAFE ABORT，绝不创建 dummy
  ↓
从 dummy IDirect3DDevice9 vtable 只补装 Reset / EndScene
```

此外，Renderer 安装顺序已提前到 NPC DialogueIndex 全量扫描之前，减少 late bootstrap 的实际触发概率。

### 新日志

```text
NPC_SUBTITLE_RENDERER_EARLY_INSTALL ... before_dialogue_index=1
NPC_SUBTITLE_D3D9_BOOTSTRAP_BEGIN ... mode=INTEROP_SAFE_RAW_EXPORT
NPC_SUBTITLE_D3D9_BOOTSTRAP_CREATEDEVICE_CLEAN owner=d3d9.dll chain_bypass=1
NPC_SUBTITLE_D3D9_BOOTSTRAP_OK ... create_hook_side_effect=0
```

若发现已有外部 CreateDevice Hook：

```text
NPC_SUBTITLE_D3D9_BOOTSTRAP_SKIP_FOREIGN_CREATEDEVICE ... action=IAT_ONLY no_dummy_device=1
```

这条 WARN 是**安全保护生效**，不是要求强行修掉的错误。

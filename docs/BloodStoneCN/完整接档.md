## 0. W1.2a 实机失败与 W1.2b 决策（2026-08-16）

用户实机确认：W1.2a 虽然能编译，但出现两项不可接受的中文覆盖回归：

- 关卡选择界面重新出现英语；
- 上一个 W1.1 仍正常的任务说明重新出现英语。

这两项回归与 W1.2/W1.2a 为性能/混杂问题新增的三类**语义性优化**高度相关：

1. `authoritative LOC pointer -> SubmitText 直接放行`；
2. `ThreadCoverageCache` 正/负缓存；
3. `sparse CJK mixed guard / pristine source retry`。

其中第 1 条的设计前提已被实机否定：`ExternalLoc` 返回的 LOC 指针并不等价于“最终显示文本”。R10.4/W1.1 的 TextCoverage 仍需对部分关卡名、任务 carrier、说明文本、动态结构字段做二次补全。跳过 SubmitText TextCoverage 会直接造成英文回归。第 3 条在无法完整救回时会回到 pristine English，也违反“已有中文不可回退”的最高约束。

因此 W1.2b **不是继续给 W1.2a 打补丁**，而是回到已实机正常的 W1.1 文本语义：

```text
W1.1 Source First / Hash Second
+ W1 武器/弹药生命周期
+ W1.1 early D3D / 双层 font gate
+ W1.1 SubmitText 两阶段 TextCoverage
```

并只保留一个不改变文本结果的性能动作：默认关闭 `LogMisses`、`LogActionTokens`、`LifecycleProbe`。这样可以直接检验此前关卡选择 20+ FPS 是否主要来自高频诊断，而不会再拿中文覆盖做性能交换。

### W1.2b 明确撤销

源码中不得存在：

```text
IsAuthoritativePointer
SUBMIT_AUTHORITATIVE_FASTPATH_ACTIVE
ThreadCoverageCache
TEXT_COVERAGE_PARTIAL_REJECT
TEXT_COVERAGE_PARTIAL_FINAL_GUARD
PRISTINE_SOURCE_RETRY
```

### 当前最高优先级

1. 关卡选择、任务说明必须恢复到 W1.1 的中文覆盖；
2. 枪械/弹药不能重新坏掉；
3. 口口口不能回归；
4. 在上述三项不退步的前提下，再确认仅关闭高频诊断后关卡选择 FPS 是否恢复；
5. “中英混杂”仍是已知 P0，但下一轮必须按具体来源做窄修，禁止用全局英文回退式 guard。

## 0.1 W1.1 本轮紧急修复：为什么 BFA“加载了”仍显示口口口

W1 实机日志已经形成直接证据：

- `BFA_CPU_OK glyphs=2512` 只证明 `fonts.bfa` 已经被 CPU 解析；
- 随后的 `FONT_GATE_WAIT ... ATLAS_NOT_READY` 说明中文 GPU atlas 尚未绑定；
- W1 在 LOC/BLI/TextCoverage 全部解析完成之后才安装 `Direct3DCreate9` IAT，本轮从 `BFA_CPU_OK` 到 IAT 安装约 1.2 秒；
- 整份 W1 日志没有 `D3D9 CreateDevice hook installed`、`BFA_GPU_OK`、`FONT_GATE_READY`；因此 BSCN 实际错过了本次真实 Device 创建；
- `GetText` 正确执行了 `FONT_GATE_SKIP_GETTEXT`，但 `SubmitText` 仍继续运行 TextCoverage，并把版权页原英语改成完整中文；这些 CJK 被交给尚未绑定 BFA 的原生字体，因此画面表现为口口口。

所以这次不是字库字符缺失，也不是 `fonts.bfa` 损坏，而是 **CPU 字库加载成功 ≠ GPU 字体渲染链 ready**，并且 R10.4/W1 的 font gate 只封住 GetText、没有封住 SubmitText。

### W1.1 只修这条时序，不回退 R10.4 中文覆盖

1. `atlas_.LoadCpuResources` 后立即 `NativeFontBridge::Prepare`；
2. **在 ExternalLoc/BLI/TextCoverage 解析之前**安装 D3D9 IAT；
3. IAT/vtable 使用 CAS 原子链式 Hook，避免多 ASI 并发覆盖；
4. `MaintenanceTick` 先尝试 NativeGlyph，再判断 GPU atlas 是否 ready；字体未 ready 时不安装 GetText/SubmitText 文本 Hook；
5. SubmitText 自身增加第二道 font gate，Reset/极端竞态期间 `rendering_ready=false` 时强制原文直通，绝不产生中文口口口；
6. `SOURCE_FIRST_HASH_SECOND`、TextCoverage、W1 动态标量旁路、技术身份延迟策略全部保持不变，因此本轮不拿“回英文”换取字体安全。

实机预期启动顺序：

```text
BFA_CPU_OK
Direct3DCreate9 IAT hook installed mode=EARLY_R10_4_W1_1 ...
R10_4_W1_1_EARLY_D3D_READY stage=BEFORE_LOC_BLI_COVERAGE_PARSE
...
D3D9 CreateDevice hook installed ...
D3D9 Reset hook installed ...
BFA_GPU_OK ...
FONT_GATE_READY localization_output=ENABLED
UNICODE_LOC_HOOK_OK ...
SUBMIT_TEXT_HOOK_OK ...
Initialization state ... font_render_ready=1
```

如果仍没有 `BFA_GPU_OK/FONT_GATE_READY`，此版本会保持游戏原文而不是生成口口口；但这种情况仍视为 **D3D 字体链失败，不能接受为发行结果**。

## 0.2 本次构建脚本修正（不改变 W1 运行时代码）

用户首次编译时 CMake 报错，把：

```text
-S <源码目录> -B <build目录> -A Win32
```

错误地解析成一个整体的 source directory。根因不是 CMakeLists，也不是 W1 源码，而是 Windows BAT 的 `%~dp0` 自带末尾反斜杠；原脚本直接将 `"%ROOT%"` 传给 CMake，末尾 `\` 在 Windows 参数解析中会干扰收尾引号，从而把后续 `-B/-A` 吞进 `-S` 参数。

现已统一改为项目既有安全写法：

```bat
for %%I in ("%~dp0.") do set "ROOT=%%~fI"
set "BUILD=%ROOT%\build"
```

这样 `ROOT` 不再带末尾反斜杠。**本修正版仅修改构建脚本、验证项与文档；W1 C++ 运行时代码、R10.4 文本行为和 HUD 实验逻辑完全不变。**

## 10. W1 的根因假设

强假设：

```text
UIWeaponPanel / 类似 HUD 对象
  原游戏 GetText 返回 game-owned mutable/rebindable wchar_t*
       ↓
R10 source-first 找到正确中文
       ↓
GetText 直接返回 LOC std::wstring::c_str()（plugin-owned persistent pointer）
       ↓
某些 UI 对象缓存/复用该地址或其关联状态
       ↓
换枪/刷新时名称和状态与真实 weapon 生命周期失配
```

R7.2/R8 恰好在 stale hash 时 KEEP_ORIGINAL，使 game pointer 活到 SubmitText，之后才 TextCoverage 中文化。这提供了历史成功先例。

弹药更直接：纯数字是实时数据，不应该进入任何翻译 resolver 或 process-lifetime stable map。

尚需 W1 实机日志证明。

## 11. W1 实现

### 11.1 动态 scalar game-owned bypass

允许：

```text
10

100%
01:23
[7]
10|30
-1
```

出现字母/CJK即拒绝归类。`P99 / 49m / Ammo 10` 都不是 scalar。

动态 scalar：

```text
GetText       保留原 pointer
TextCoverage  bypass
SubmitText    原 pointer
stable map    bypass
```

### 11.2 技术身份 late delivery

通用 token，不维护枪名列表：

```text
P99
MP7
G36C
A.R.
```

只在：

```text
source-first 已选中候选
AND runtime hash 与所选 key_hash 明确不一致
AND source 含技术身份
AND LOC 中文保留同一身份
AND source 不只是纯身份 token
```

时：

```text
GetText    game pointer
SubmitText exact/deferred context 注入同一 LOC 中文
```

即中文“晚一点交付”，不是放弃。

### 11.3 内容相同则不换 pointer

`MP7 -> MP7` 这类无可见变化的候选直接使用游戏 pointer。

### 11.4 HUD 生命周期诊断

新增：

```text
HUD_GETTEXT_TRACE
HUD_GETTEXT_SELF_TRANSITION
HUD_IDENTITY_DEFER_GETTEXT
HUD_DYNAMIC_SCALAR_GETTEXT_BYPASS
HUD_SUBMIT_TRACE
```

技术身份 translated 日志按 `wcscmp` 内容变化判断，而非 pointer 差异。

> 源码可进入 Windows x86 编译，但不能把静态验证冒充实机/ABI PASS。

## 14. NPCSubtitles 独立插件已确认事实

虽然 W1 首轮测试建议不加载 NPCSubtitles，但以下历史结论必须保留：

```text
NPC Dialogue callsite 0x0093A2A1 -> 0x00F12820
DIALOGUE.arg0 == *_script_dialogue.loc key_hash
```

重复站点：

```text
0x009302B5
0x00A706E8
```

生产不能三处都 hook，否则重复捕获。

NPC D3D 独立稳定基线曾为 `NPCSubtitles 0.2.2 D3D9InteropSafe`。Dummy device 通过别的 ASI hook chain 会污染 BSCN GPU 字体上下文；0.2.2 改用 raw D3D export + foreign-hook guard。

后续独立互操作约束：

- BSCN 可作为可选 D3D host；
- NPC 能 attach C ABI 就不再装自己的 D3D hook；
- host 不可用时回退 0.2.2 独立 D3D 路线；
- x86 stdcall decorated export 需兼容。

当前 W1 不修改 NPCSubtitles。

## 16. 已明确失败/禁止回退路线

1. **T4 PE section stitching**：静态似乎可行，实机 `0xc000007b`；禁止。
2. **T5 巨型重构/合并**：曾出现体积暴涨、启动崩溃；禁止直接回退。
3. **全局 spacing Hook**：破坏对齐/换行/裁剪；禁止。
4. **FIRST_BLI_CANDIDATE**：同英语多语境会串线；禁止。
5. **hash 作为对象身份**：R7.1 P99→MP7 已否证；禁止。
6. **全局 hash disagreement -> KEEP_ORIGINAL**：会让城市/任务等 R10.4 中文回退；禁止。
7. **UIDialogue final-object 常驻生产**：位置晚、上下文丢失、对象侵入；退休。
8. **TextPathProbe/Renderer probe 常驻**：研究完成，不为日志常驻改 call target/slot。
9. **任意 substring 翻译**：会污染长文本；禁止。
10. **R9 broad dialogue auto-defer 解决 CG timing**：实机失败；禁止再当根解。
11. **SubmitText 作为任意 UI overlay factory**：NPC raw SubmitText 实机不可见，已否证。
12. **独立 NPC dummy-device 经别的 hook chain**：污染 BSCN font GPU context；禁止。
13. **R11 CleanResolver 主线**：覆盖退化；作废。
14. **用减少 TextCoverage/诊断换 FPS**：当前主目标仍是中文覆盖，不接受用漏翻换性能。

# BloodstoneCN R10.4 W1.2b 架构与修复说明

## 0. W1.2b：文本语义回滚到 W1.1，性能只关诊断

W1.2/W1.2a 的 authoritative pointer fastpath、coverage cache、sparse-mixed guard 已全部撤销。`external_loc.cpp`、`submit_text_bridge.cpp`、`text_coverage_resolver.cpp` 等决定可见文本结果的核心文件恢复为 W1.1 版本。

W1.2b 仅把以下默认诊断关闭：

```ini
[TextCoverage]
LogMisses=0
LogActionTokens=0

[HudLifecycle]
LifecycleProbe=0
```

这三项只影响日志/探针，不改变翻译候选、TextCoverage、GetText/SubmitText 交付和字体行为。

---

## 0.1 W1.1 相对 W1 的唯一新增架构修复

生产文本架构仍是 R10.4 + W1，未引入 R11 CleanResolver。W1.1 只把 D3D/font gate 从“附带状态”提升成真实生命周期前置条件：

```text
BFA CPU
  ↓
立即 Hook Direct3DCreate9
  ↓
LOC/BLI/TextCoverage 重型解析（此阶段不影响是否抓到 Device）
  ↓
NativeGlyph + GPU atlas ready
  ↓
FONT_GATE_READY
  ↓
才允许安装 GetText / SubmitText
```

同时 SubmitText 自身在 `rendering_ready=false` 时原文直通，覆盖 Reset/极端竞态。

## 1. 本版定位

W1 是 R10.4 的局部 HUD 生命周期验证版，不是新主架构。生产文本链继续只有：

```text
GetText 0x00E87740
    ↓
R10.4 Source First / Hash Second
    ↓
SubmitText 0x00E85900
    ↓
R10.4 TextCoverage / stable effective string
```

W1 只在两类 HUD 数据上插入窄旁路：动态标量与明确 stale-hash 的技术身份标签。

## 2. 不变部分

- 86 个现有 LOC 仍是唯一中文正文来源；
- BLI3 只做 source/key/hash/context/defer；
- Source First / Hash Second 不变；
- TextCoverage 绝大多数解析逻辑不变；
- GetText/SubmitText 地址和 ABI 不变；
- M2F1 NativeGlyph、FontAtlas、D3D9 生命周期未改；
- 独立 ASI 互操作 ABI 未改；
- GamepadIcons 不在本包修改范围；
- NPCSubtitles 仍是独立 ASI。

## 4. 配置

```ini
[HudLifecycle]
BypassDynamicScalars=1
DeferTechnicalIdentityLabels=1
LifecycleProbe=0
```

首轮实机保持默认。做 A/B 时可以单独关闭某项，但不得同时更改其他翻译设置，否则日志无法归因。

## 5. W1 不是武器名单

技术身份 token 使用通用字符串结构：

- 字母+数字：`P99`, `MP7`, `G36C`；
- 短大写标识 + 分隔符：`A.R.`。

运行时代码没有 P99/MP7/M16/AK47 等具体 weapon list。

## 6. 中文不回归保障

W1 只有“延迟中文”与“动态数据不翻译”两类动作。技术身份 defer 前已经由 R10 Source First 选中了当前 LOC 中文，随后把这条 exact mapping 放入现有 deferred context；SubmitText 再注入。非技术城市/任务/菜单的 stale hash 路径仍完全按 R10.4 执行。

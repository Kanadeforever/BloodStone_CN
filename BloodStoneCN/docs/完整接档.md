# BloodstoneCN M1 v1.2 无资产公开工具版完整接档

**基点**：用户提供的 BloodStoneCN_M1_v1.2 原生文字效果修复完整工程包（2026-10-11）。  
**本次版本**：M1-v1.2-Toolkit-public3-PakFix（2026-10-15）。  
**本次目标**：把个人完整汉化工程改为不附带任何游戏资源的公开工具，使使用者用自己的游戏、译文与字体复现相同原生汉化技术。没有新增 QOL／手柄或其他游戏版本适配。

## 1. 当前架构和数据边界

| 目录／模块 | 内容和职责 | 公开状态 |
|---|---|---|
| source/BloodstoneCN | Win32 ASI 源码、签名和构建工具 | 完整保留 |
| source/tools、tests、config | 工程检查、公开打包与测试 | 完整保留 |
| toolbox/gui.py | 中文 GUI，初始化、译文编辑、字体配置、转换、验收、日志 | 唯一界面入口 |
| toolbox/toolkit.py | GUI／CLI 共用的事务工作流 | 独立于 source |
| toolbox/core | 原生 PAK、LOC/JSON、EUR、GDI、编辑模型和后台任务 | 唯一维护源码，无发行副本 |
| release/Runtime | 冻结 ASI 和空 BSCNContents | 不含工具或游戏资源 |
| docs、.build | 正式文档和开发临时目录 | 公开文档；临时数据不公开 |

游戏原文件只读。所有个人输入在 toolbox/input，唯一译文在 toolbox/translations，状态在 work，输出在 output，运行缓存和偏好在 .caches。不存在文本与字体各自一份 JSON 的同步问题。工具只用 Python 标准库，GUI 需要自带 Tkinter，GDI 需要 Windows；普通使用者无需编译链。

工具箱整目录可以单独复制，单项转换不依赖 source、release 或 ASI。完整安装目录组装时才读取指定插件；默认优先 input/plugin/BloodstoneCN.asi，其次完整包的 release/Runtime/BloodstoneCN.asi。GUI 也能选择外部 ASI。插件来源只读，不把工具安装进 Runtime。

## 2. 不变的技术路线

1. 保持游戏 EN 语言、原有语音／图标／字幕事件身份；中文填入原生 EN LOC。
2. 原 gamedata.pak 和 root.pak 保持不变，不重封、不写回、不安装替换 PAK。
3. 通过 ASI 改变原生 LOC 目录与 EUR 资源名称；不在 GetText／SubmitText 热路径逐词条替换，不安装字形查找 Hook。
4. ASI 与 BSCNContents 同级，以 ASI 自身真实路径推导资源目录；相对／绝对路径处理、Unicode 到 ANSI／8.3 回退全部沿用 v1.2。
5. 三个 EUR 字体面同时扩容，保留原西文压缩纹理块及第三面的原始字距数据；维持右边界字形记录和前置索引规则。
6. 人工只编辑 JSON 的 translate；整套 86 份资源缺失、额外、身份或原文错误均阻止回编。
7. 普通启动不写日志；只有独立 --log 参数才写 ASI 同目录的 BloodstoneCN.log。
8. 保留 v1.2 的原生随机字母分支修复，不改变其余逐字效果分支。

## 3. Win32／ASI 逆向合同

原样本是 PE32/x86 Bond.exe，早期样本尺寸 16,496,128 字节。源 EXE 代码段在磁盘上受保护／加密，运行时由 rld.dll 解密；旧工程基于 2026-10-04 明文转储建立精确签名。EXE、DLL、明文转储、截图及任何游戏本体均不在公开包中。

原模块 ImageBase 为 0x00400000。五个站点都是 push imm32，运行时按实际模块基址加 RVA 访问：

| 站点 | VA | RVA | 原有语义 |
|---|---|---|---|
| 普通 LOC 目录 | 0x00C33948 | 0x00833948 | gamedata\xt\Loc\ |
| 关卡 LOC 模板 | 0x00C33ACC | 0x00833ACC | gamedata\xt\Loc\Levels\%s\ |
| 多人 LOC 模板 | 0x00C33ABD | 0x00833ABD | gamedata\xt\Loc\MultiplayerLevels\%s\ |
| EUR BPR 资源名 | 0x00C36870 | 0x00836870 | Ui/Data/ui_font_eur |
| EUR DAT 资源名 | 0x00C36BA4 | 0x00836BA4 | Ui/data/ui_font_eur.dat |

profile 保留确切机器指令和字符串地址，属于补丁定位元数据，不是资源模板。插件同时检查 PE、原始字符串、操作码和指向位置，等待解密最多 15 秒。VirtualProtect 修改失败会回滚，五处成功后清零失败站点。未知代码、别的 MOD 抢占或路径无法无损表示时安全拒绝对应操作。

DllMain 仅初始化路径和 Worker；Worker 负责资源／指令操作。ASI 不使用 CRT，直接导入少量 kernel32 API。没有把大型翻译表、字体、纹理或 LOC 编译进 ASI。本次没有修改任何 C++ 运行时代码和配套头文件，正式 ASI 与输入包逐字节相同。

### 原生逐字效果

分发指令 VA 0x00C6993E，跳转表 VA 0x00C69C74：

| 分支 | 原目标 VA | 本版行为 |
|---|---|---|
| 透明度 | 0x00C6994E | 保留 |
| 颜色 | 0x00C69976 | 保留 |
| 随机字母 | 0x00C69A5C | 改至原有继续位置 0x00C69BB6 |
| 旋转 | 0x00C69B3E | 保留 |

原随机分支在 0x00C69A9E 把临时代码点截断至 ASCII z，中文经过该逻辑时出现连续 Z。本插件只改第三个 DWORD，核验分发代码、全部原目标、随机分支开头、截断和继续指令，失败回滚。此修复失败不会中断已成功的五条资源路径。它的实机验收状态与原 v1.2 相同，仍待确认。

## 4. 原生 LOC／JSON 合同

参考 gamedata.pak 是 2KAP v2，299 个有效资源、234 个空占位，含 86 个 LOC 与 213 个其他有效资源。资源名表有固定 XOR 编码；这只是已验证格式规则，不包含正文。FilePak 新增 rb 只读文件映射，用于 root.pak 等大型封包；只解压明确选择的条目。NativePak 原内存入口继续供 LOC 工具使用。

OLTX 资源包括 KeyTable、八种语言目录及正文。参考 86 份有 7,975 条 EN 文本；回编按 unsigned 32 位 hash 升序建立 EN 索引，复制原 KeyTable 与非 EN 七块。历史曾有 65 份中文索引无序，排序修复后已获实机确认。

JSON 格式为 BSCN-LOC-JSON-v1，每资源独立文件，保留 gamedata/xt/loc 目录树。字段包含 format／resource／language／template_sha256／baseline_sha256 和 entries。每条 hash／key／original 不变，translate 可改；重复字段、重复或溢出哈希、模板不符、缺项、NUL 与非法代理项均拒绝。

公开初始化只从用户当前游戏导出 original，并设置 translate=original，不使用旧中文 LOC ZIP。回编 baseline_dir=None，直接由原 PAK 和当前 JSON 生成；这是原独立 LocTool 已有路线。旧完整工程曾用中文基线保留原字符串存放顺序；因此新工具同译文的整文件哈希可能不同，但所有原生资源键、EN 正文、索引排序与其他语言字节相同。不能把无关的字符串存放次序差异误判为技术效果不同，也不能声称 LOC 文件一定逐字节相同。

旧译文中的 7 条多人 token 差异只作为可选旧工程对照测试依据，本公开工具没有预置这 7 条内容。新的翻译也应关注 ~~{...}~~ 控制标记，默认报告差异，不擅自改写。

## 5. EUR 字库合同

三个面依次为 E_Century_Gothic、E_Century_Gothic_Bold、E_Microgramma。原纹理每面 512×1024，候选优先扩为 2048×2048；DAT 记录 28 字节，字体面头 296 字节，BPR 具有三层 DXT1 Mipmap。

查询 cp 依赖前置入口 cp，实际图像保存在边界 cp+1。只补其中一个会错字／方框。原西文 DXT1 块按行原样放在左上角；第三面的 3,528 字节配对区和计数 588 的尾记录保留，三个字体面都扩容。

用户字体通过 AddFontResourceExW 的 FR_PRIVATE 载入，读取真实字体名称及 GDI 实际选择，GetGlyphIndicesW／GetGlyphOutlineW 读取字形，退出卸载。灰度、单色与末行 padding 边界处理沿用 v1.2 工具修复。字格 36×44，默认像素字号 32。

精准模式只收集 translate 所需的非 ASCII 码点；常用字模式含 GB2312 一级和标点；GBK 模式枚举 CP936 双字节映射。缺字体／缺字报错，不能依靠系统静默替代。个人 BFA 回退保留为可选输入，公开包没有 BFA。相同原始模板、BFA 输入和 2048 参数经过可选参考测试可复现原正式 DAT/BPR 的相同字节。

继续保留两个与本地重建相关的容量修正：

- preserve_original_blocks 原来写死新纹理行为 2048；现在显式传入实际边长，保证 4096／8192 的西文块也按正确行距复制。2048 默认结果不变。
- 临时字形图集原来仅按像素总面积挑尺寸，接近容量时会因每行字格余量而误报不足；现在也按实际行列容量升级。

较大图集依然只是实验规格，修正离线编码不等于已有游戏运行证据。

## 6. 统一工具箱与 GUI 合同

prepare 只执行一次：验证全部来源，在 toolbox/.caches 暂存，成组发布 input/gamedata.pak、input/template、唯一 translations 和 work/project.json。初始化拒绝覆盖个人项目，原始游戏只读。原文副本导出是单独操作，既不重复初始化，也不重置 translations。

build 在临时目录复制工具核心及当前唯一输入，调用真实 LOC／字体核心。全部通过后检查译文、KeyTable、语言块、字形入口、DXT1 块、配对表、所选 ASI 与构建前后输入快照，成组发布 output/loc、output/font、output/Runtime 和 build_manifest.json。输入发生变化或任一步失败，不更新完整成品。单项 build-loc／build-font 无需 ASI，只更新自己的输出与报告。

verify 核对当前输入和完整构建记录，检查安装文件增删改，再独立校验原生语义。它只证明磁盘成品与输入匹配，不声称游戏 VFS 实际读入。

GUI 主线程仅处理 Tk 控件和队列；后台线程读取子进程标准输出，将日志和返回码放入队列。耗时转换不阻塞主界面；任务期间禁用编辑与按钮，窗口关闭不会杀死进行中的工作。GUI 采用 Windows DPI 感知，使用原生主题和一致容器背景；实际高分屏布局仍待 Windows 验收。

译文编辑模型只修改 translate，保存前复用 import_one 校验资源、原文、键及所有记录。使用读取指纹拒绝覆盖外部编辑器新修改，临时文件与正式 JSON 同分区，最后 os.replace 一次替换。切换文件／构建／退出处理未保存内容；选择放弃则重新读取磁盘。导入字体只替换本目录副本，字号 16～34；GUI 完整构建自动应用当前字体和字号。

输入输出树拒绝符号链接与 Windows 重解析点。封包资源路径拒绝穿越、绝对路径、UNC、盘符、空路径段和控制字符；单个前导反斜杠作为引擎虚拟根剥离后检查。允许工具位于游戏目录下的独立子目录；限制针对实际输入输出冲突，不再按整个游戏根目录一概拒绝。公开打包白名单不包含任何个人输入、译文、字体、输出、缓存或路径偏好。

## 9. 构建与发行规范

source/build_all.bat 检查独立工具目录并执行自包含测试，不同步第二份 Python 程序，不依赖个人数据。--compile-plugin 可在已有 MSVC x86 环境重建插件；独立 build.bat 与交叉编译脚本保留，临时文件在 .build，编译产物在 release/Runtime。运行时个人结果在 toolbox/output，公开 ZIP 在 release/dist。

## 11. 原始根包合同与初始化修复

用户给出的原始文件指纹已与先前上传的 bloodstone_cache_gamedata_root_pak.zip 内两个文件逐一核对，完全一致：

| 文件 | 字节数 | SHA-256 |
|---|---|---|
| gamedata.pak | 11,495,424 | 070b7592885c36e2b788b43a0b9ed8f28cf36b8b087a734e4c6e700ed2629fb4 |
| root.pak | 236,556,288 | ff8a5ba04a336e05fae2cdc52720373742adc62cc9c4b153f4167d486552df10 |
| 提取的 ui_font_eur.dat | 29,120 | a12fefdfc15d1fbd55d19739d9031faf637f837d37b2febba4a1f2fc8d50b7bb |
| 提取的 ui_font_eur.bpr | 1,032,349 | d4e46ebcaa4b82e75dc68fb5c8fc725c03df5d77f405eef0ddcc906f8768509f |

gamedata 使用 2KAP v2，root 使用 2KAP v3。仅修改版本白名单不能完成适配：后者名称表保存单个名称片段，完整路径必须沿父目录索引还原。

root 的对齐页为 0x800，名字表长度 301,538，索引头位于 0x4A800；头中声明 10,934 条和 437,360 字节记录区，实际记录从 0x4A80C 开始，每条固定 40 字节，记录区结束于 0xB547C。包括 525 个目录和 10,409 个文件；全部文件解压后合计 516,594,200 字节。

| 记录内偏移 | 已确认含义 |
|---|---|
| +0x00 | 名字表中的名称片段偏移 |
| +0x04 | 父目录相对记录区开头的字节偏移，按 40 对齐 |
| +0x08 | 未压缩字节数 |
| +0x14 | 64 位数据块编号，乘对齐值定位数据；-1 表示目录 |
| +0x20 | 压缩字节数 |
| +0x24 | 固定末尾字段，不作为可变扩展记录的标志 |

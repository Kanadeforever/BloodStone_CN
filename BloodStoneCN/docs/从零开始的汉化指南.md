# 从零完成 BloodstoneCN 汉化

## 准备条件

自备《007 Blood Stone》PC 版原始 gamedata.pak、root.pak，使用 Windows 和带 Tkinter 的 64 位 Python 3.10+，另外准备自己的译文和一份支持目标字符的 TTF/OTF/TTC。游戏需要已有的 x86 ASI 加载器；公开包不包含加载器。无需管理员权限、编译器、pip 或网络。

解压到独立文件夹（允许位于游戏目录下），运行根目录下 `toolbox/start.bat`。路径允许中文和空格。

## 一次初始化

在“项目初始化”选择含 Bond.exe 的游戏目录，点击初始化。该步骤完成全部模块的共同准备，不再要求文本工具和字体工具分别初始化。

1. 只读解析 gamedata.pak，确认 86 LOC、7,975 条 EN 记录。
2. 只读映射 root.pak，按明确资源索引提取 `ui/data/ui_font_eur.dat`、`ui/data/ui_font_eur.bpr`；不复制整个 root.pak。
3. 校验三个 EUR 字体面、512×1024 模板尺寸、DAT/BPR 字节往返、第三面配对表。
4. 在 toolbox 保存原 PAK 副本、两份字体模板、一份完整译文目录及项目记录。
5. 全部验证成功后成组发布；失败不遗留半套初始化输入。

`toolbox/translations/gamedata/xt/loc` 是唯一人工译文源；字体工具直接使用它。初始化的 translate 等于 original，不含原作者译文。已有项目拒绝覆盖，另一个项目使用另一份解压目录。

如实际 root.pak 布局不支持，使用手动来源，指定本人 gamedata.pak 和从本人游戏提取的 `ui_font_eur.dat/.bpr` 目录。当前已支持并验证用户原始 root.pak 的目录索引结构，自动入口与手动模板入口均可用。

## 编辑译文

在“译文编辑”页面选择资源和记录，编辑右侧译文并保存。可按键、原文和译文筛选。保存会执行真实 LOC 导入器校验，并防止覆盖外部编辑器已保存的新内容。

也可外部批量编辑 JSON。只改 `entries[*].translate`，保留 format、resource、language、所有 SHA-256 身份字段、hash、key、original 及文件集合。禁止增删记录、遗漏文件、NUL 和非法代理项。`~~{动作名称}~~` 控制标记应保留，差异作为警告进入报告，不自动改写译文。

“导出原文副本”用于另存未译原文到 `toolbox/output/loc/untranslated_json`，不会重置 translations，也不会覆盖已有副本。无需为了重新查看原文而重复初始化。

## 提供字体并构建

在“构建与验收”选择一份个人字体，像素字号默认 32，可调 16～34。点击完整构建会先应用界面当前选择，随后回编 LOC、生成三面字库并验收。也可以先导入字体保存配置，再开始构建。

GDI 使用私有字体注册，核验实际字体名称，缺字或异常明确报错；退出时卸载，不安装系统字体。精准模式提取当前 translate 所需非 ASCII 字符。常用字为 GB2312 一级及标点；完整 GBK 枚举 CP936 合法双字节映射。无字体时，拥有本人 BFA 的用户可将其放入 `input/template/fonts.bfa` 供精准模式回退，普通用户无需 BFA。

完整构建检查 86 LOC 逐条文本、原始 KeyTable、EN 无符号排序、其余七块语言字节、三面 cp/cp+1 字形记录、DAT/BPR 尺寸、三层原西文 DXT1 块、第三面字距和尾记录、ASI 指纹及构建前后输入快照。成功发布 `toolbox/output/Runtime` 和构建报告；失败保留旧完整成品。再次编辑输入后，旧成品即使存在也必须重建，验收会识别过期。

原项目已确认的是 2048 三面方案。4096／8192 大图集保留为实验规格，需要游戏内单独验收。默认使用精准模式，尽量采用 2048 能容纳的字集。

## 安装与诊断

只安装 `toolbox/output/Runtime` 中的 ASI 和整个 BSCNContents，使它们同级。Runtime 中没有任何工具代码；不要安装 toolbox、原始 PAK、源码或报告。游戏语言保持 EN，不替换和重封 PAK，移除冲突的旧汉化／字体插件。

ASI 按自身位置确定资源目录，可由现有加载器放入 scripts、plugins 等任意可加载目录；DAT/BPR 必须成对安装。卸载移除 ASI 及其同级 BSCNContents。

启动时独立使用 `--log` 可在 ASI 旁写 BloodstoneCN.log；普通启动不会新建、更新或删除旧日志。

- `FIVE_PATHS_REDIRECTED` 代表五处路径已改，不单独证明引擎随后读取所有资源。
- `random_letter_effect=DISABLED_RANDOM_LETTERS` 代表分发表第三项已改，是否消除 Z、是否保持渐显需看游戏画面。
- 缺字时检查字体覆盖和当前译文是否新增字符，重新生成匹配的 DAT/BPR。
- 指令不匹配时保留日志和 EXE 信息，不能跳过签名盲打补丁。

## 独立工具箱与命令行

`toolbox` 整目录可独立使用，不依赖 source。单项导出／回编／字库生成不需要 ASI；完整组装时自行指定 ASI，或完整包默认读取 `release/Runtime/BloodstoneCN.asi`。需要携带插件的独立个人副本可以将它放入 `toolbox/input/plugin/`。

详细 GUI 操作和全部工作路径见 `toolbox/使用说明.md`。从 toolbox 执行：

```bat
python -B -X utf8 toolkit.py prepare --game "D:\Games\007 Blood Stone"
python -B -X utf8 toolkit.py build --font "D:\Fonts\MyFont.ttf" --pixel-size 32 --mode precise
python -B -X utf8 toolkit.py verify
python -B -X utf8 toolkit.py build-loc
python -B -X utf8 toolkit.py build-font --mode precise
python -B -X utf8 toolkit.py export
python -B -X utf8 toolkit.py status
```

手动指定文件时，用 `prepare --gamedata "D:\Game\cache\gamedata.pak" --root-pak "D:\Game\cache\root.pak"`，或将 --root-pak 换成 `--template-dir "D:\MyTemplates"`。完整构建可加 `--plugin` 明确指定 ASI。

## 对外发布

运行 `python -B source/tools/package_release.py`，输出 `release/dist/BloodStoneCN_M1_v1.2_PublicToolkit_GUI_PakFix_20261015.zip`。仅白名单程序和文档进入 ZIP，排除个人 PAK、模板、原文、译文、字体、BFA、配置状态、日志和生成物。个人项目备份应另存，不得当作公开工具包发布。

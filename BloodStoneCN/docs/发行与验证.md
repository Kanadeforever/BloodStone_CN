# 公开发行与验证

## 目录与维护

根目录分为 docs、source、release、.build，另按当前用户要求放置独立 toolbox。source 只保留插件工程和开发相关的构建、测试、打包工具；所有实际汉化工具在 toolbox 维护唯一源码，不复制第二套发行脚本。

release/Runtime 仅保留冻结的 ASI、空资源目录和中文说明。toolbox 公开输入和 translations 均为空，使用后产生的 work、output 和 .caches 永不自动加入公开包。

## 开发检查与编译

Windows 默认只检查工具箱并测试，不要求重编冻结 ASI：

```bat
source\build_all.bat
```

通用 Python 入口：

```text
python -B source/tools/bootstrap_toolbox.py
python -B source/run_tests.py
```

bootstrap 只补齐空工作目录和检查路径，不复制代码，不覆盖个人输入。Python 代码直接运行。测试临时文件在 .build，结束后清理。

需要从源码编译 ASI 时，在 MSVC x86 Developer Prompt 执行：

```bat
source\build_all.bat --compile-plugin
```

也可单独调用 source/BloodstoneCN/build.bat。输出统一在 release/Runtime，临时文件在 .build/BloodstoneCN，成功后清理。交叉编译脚本 source/BloodstoneCN/tools/build_clang_cross.py 需要自行具备 clang-cl 和 lld-link，无联网安装步骤、不固定编译器路径。重新编译后的 ASI 可能因编译器而改变字节，必须先独立审核，再调整打包器固定指纹。

## 可选私人对照

有自己的旧 v1.2 工程时，设置 BSCN_PRIVATE_REFERENCE 指向它再运行测试。五项可选对照只读访问旧工程：原 ASI/C++ 完全一致、真实 PAK 299 资源一致、86 LOC 的文本／键／其他语言等价、同模板与 BFA 的 2048 字库逐字节一致、真实输入完整初始化／构建／验收。参考资料不随包分发。

可设置 BSCN_PAK_REFERENCE 指向同时包含 gamedata.pak 和 root.pak 的个人目录，运行两项原包指纹、模板提取及游戏子目录自动初始化／回编验证；与 BSCN_PRIVATE_REFERENCE 同时设置时，整套旧工程对照会改用真实 root 自动提取入口。

可选 BSCN_BOND_UNPACKED 指向自己的明文 EXE，核验运行时签名。没有旧工程时跳过五项，没有双 PAK 时跳过两项，没有明文 EXE 时再跳过两项；不寻找、下载或生成这些私人文件。

## 安全公开打包

```text
python -B source/tools/package_release.py
```

默认输出 release/dist/BloodStoneCN_M1_v1.2_PublicToolkit_GUI_PakFix_20261015.zip，可用 --output 修改位置。工具只收录 source/config/public_files.json 明确列出的源码、程序、公共配置和中文文档。

打包器拒绝资源后缀、LOC JSON、input、translations、work、output、临时缓存、目录穿越、符号链接和重解析点；仅允许列出的公共配置 JSON；固定原 v1.2 ASI SHA-256。个人字号在 input，路径偏好在 .caches，均不在公开列表。

生成 SHA-256 清单，固定条目时间及排序，验收 CRC 和文件集合后替换完整 ZIP。脏工作目录测试故意放置私人资产哨兵，再确认任何哨兵都不会进入公开 ZIP。相同程序与文档应可重复得到相同 ZIP 字节。

新增公共代码文件需人工更新白名单。用户用过工具箱后仍可安全调用公开打包器，禁止直接压缩整个个人工作目录。

## 验证边界

自包含测试覆盖一次初始化、中文和空格路径、独立工具箱、单项转换、完整构建、事务回滚、原文件只读、过期识别、字体边界、GDI 位图缓冲、GUI 编辑模型的数据安全和后台任务日志、公开包资产隔离。真实输入对照仍只读进行。

当前执行环境没有图形显示和 Windows：GUI 布局未实际渲染验收，Windows 字体对话框、DPI 与真实 GDI 仍需实机确认。真实 root.pak 的 10,409 个文件已逐项解压，EUR 模板指纹一致，自动初始化和整套构建已跑通；这些是文件与离线流程验证。原 v1.2 随机字母效果、4096／8192 图集也不能写成实机通过。测试结果见资产审计文档。

# 007 Blood Stone 单 DLL 手柄输入与图标项目完整接档

## 项目目标与发行边界

目标程序 `Bond.exe` 是 Win32/x86 D3D9 游戏；已经核实其导入 `DINPUT8.dll`、`XINPUT1_3.dll`、`d3d9.dll`。
最终发行仅需 `release/dinput8.dll`，不依赖任何 INI、TOML、外部 SDL3.dll 或外部映射文件。
运行时仅额外生成 `dinput8.log`，每次游戏启动通过 `CREATE_ALWAYS` 清空上一轮日志。
游戏目录不可同时放置旧 `BondGamepadIcons.asi` 或其他承担同一 XInput/DirectInput 的 JoyShim 代理，避免重复 Hook。

## 来源与基线

- 图标功能：BondGamepadIcons v1.4.20 Reset Managed Atlas 修复版；保留 512×512 DXT5 图集识别、三家族缓存与图集 Reset 事务式保留。
- 输入功能：JoyShim SDL3 3.4.18 buildfix14（2026-10-28）；静态链接官方 SDL3，不要求外置 SDL3.dll。
- 此包为专版集成候选；并非已完成游戏实机验收的发行版。

## 工作架构

`Bond.exe` 的 DInput8 静态导入触发单 DLL 加载。JoyShim 保留 DirectInput8Create 与 XInput 函数接管，单一入口先记录模块及创建日志，再启动图标 Hook 初始化和 JoyShim 后台启动。
JoyShim 输入线程通过 SDL3 官方 Gamepad API 打开设备、维护四个 XInput 槽位，并在 SRWLOCK 下发布槽位 0 的有效手柄类型、类型名称、VID、设备名称。
BondGamepadIcons 的图标线程仅读取这个快照；再按 SDL 已知类型 → 官方未来类型字符串 → 名称 → VID → Xbox 默认回退选择 Xbox/PlayStation/Nintendo 三套内嵌图标。
控制器类型与图标图集互相独立。PS6、下一代 Xbox、NS2 Pro 若被未来 SDL 以可识别类型字符串归类，仍会归到现有三大家族；未知类型安全回退 Xbox。

## Stadia 专属修复

Stadia 既可以 USB 也可以蓝牙连接；不能使用单一有线 GUID/PID 限定。
输入线程还会只在首次打开手柄时检查官方 SDL 映射字符串中的 Stadia 名称，避免驱动把蓝牙设备改报为通用 HID 名称时漏判；这一字符串由 SDL 自己提供，不加载外部文本。
专版仅对输入线程标记为 Stadia 的已接管物理手柄启用原生 DirectInput 去重。该标记参考 SDL 设备名、Google VID `18D1` 或 SDL 数据库的映射名称，其他设备默认关闭去重。
为了防止误屏蔽，最终隐藏的 DirectInput 设备必须通过手柄类别检查，并与 SDL 已发布的 Stadia 在当前连接方式下具有**完全相同的 VID、PID、唯一实例路径**；还须满足可追踪的 DirectInput GUID 约束。无线 VID/PID 可以与有线不同，但同一连接下的两侧标识必须一致；若驱动暴露两条完全不同的路径，仍会安全放行并需要实机诊断。
不修改 SDL 标准右摇杆数据路由，不对非 Stadia 设备注入新的轴校正。
SDL 3.4.18 的静态游戏手柄数据库已有 USB、蓝牙的 Stadia 映射记录。

## 图标显示机制及已确认修复

- 原生 `GetPromptIcon` / `GetPromptName` 与当前 Action/Binding 解析；提示文字使用固定键盘 Token 作为载体。
- Tips 左右切换固定 ARROWLEFT→LT、ARROWRIGHT→RT；过场 SPACE→Y、ESCAPE→START。
- 掩体教程 action 38/39 分别使用 LS_LEFT/LS_RIGHT；黑客 QTE 专用调用点使用 A/X。
- 瞄准教程 LT + RS_ALL；原图集无限弹药单元 (3,7) 永久保护。
- 原游戏的 D3DPOOL_MANAGED 图集和三套替换图集跨普通 Reset 存活。分辨率切换后不能清除已确认 managed 候选，否则游戏不会再次创建原图集。
- 固定图集的命令行参数：`Bond.exe -ps` / `-ns` / `-xb` / `-auto`，最后一个有效参数生效。无参数默认 Auto。

## 兼容边界与安全约束

合并后不再扫描进程中的外部 SDL3.dll；JoyShim 的静态 SDL3 输入线程是唯一 SDL 设备拥有者。图标渲染 Hook 只读其发布槽位，不能进入 SDL 更新或设备打开关闭路径。
保留 JoyShim 的 DInput8 系统导出表、按设备身份的原生输入过滤、XInput IAT/动态重定向，以及内嵌 SDL3 的热插拔流程。
外部 LOC/字库若继续走游戏原生渲染路径，不影响图标逻辑；但原生提示 Token 和 D3D9 Reset 仍是共享风险点。

## 构建与交付

在 Windows + Visual Studio 2026 / MSVC x86 + CMake 上运行 `source/BloodStoneInput/build.bat`。
工程自包含 SDL3 3.4.18 源码。输出只进入 `release/dinput8.dll`；编译中间文件进入 `.build/win32`。
不要硬编码 VS 安装路径。正式构建需要 Win32 桌面 C++ 编译组件、Windows SDK 和可用的 CMake。
构建脚本在 `@echo off` 之后立即执行 `chcp 65001 >nul`；先进入源码目录并保存 `%CD%` 作为 `-S` 参数，避免 `%~dp0` 末尾反斜杠与引号组合错误。默认使用 CMake 的 `Visual Studio 18 2026` 生成器和 `-A Win32`，需要其他 Visual Studio 版本时可通过 `BSCN_CMAKE_GENERATOR` 更换。只有构建成功并找到 `Release/dinput8.dll` 时才复制到 `release/`，不主动删除旧发行文件。

## 已发现的构建脚本问题与修复

Windows 实编首次运行时，旧 `build.bat` 使用 `cmake -S "%~dp0"`；由于 `%~dp0` 以反斜杠结尾，CMake 会收到把 `-B`、`-A`、`-D` 拼进源目录的错误参数。现已改为规范化源码目录，并补齐 UTF-8 控制台代码页 `chcp 65001`。此项仅修复脚本命令行参数，不能作为完整编译或实机验收结果。


## Win32 首轮实编反馈与当前源码修复

2026-10-28 用户在 Visual Studio 18 2026、Windows SDK 10.0.26100.0、MSVC 19.51 下实际运行构建：
- CMake 配置、Win32 工具链选择、SDL3 3.4.18 静态库构建全部成功；因此不是 SDL3 构建问题。
- `BondGamepadIcons.cpp` 的 `ResolveAutomaticControllerFamily` 结束花括号误放入 `#else`：启用 `BSCN_SINGLE_DLL` 后函数未闭合，第 1515 行起出现大量 C2601／C2598 连锁错误。已把函数的最终 `}` 移出条件编译分支，使单 DLL 与独立图标路径都闭合。
- `xinput_exports.hpp` 和 `xinput_proxy.cpp` 对七个系统 XInput API 的重声明与 Windows SDK 的异常规范不一致，引发 C2382。已针对 MSVC 使用与 SDK 相同的 `noexcept`，其余工具链保持原声明；用模拟旧版 SDK、MinGW 与现代 MSVC SDK 的头桩分别检查。
- `config.cpp` 的专版分支 `return` 后仍编译通用配置判断和异步日志实现，触发 C4702，因 `/WX` 升级成 C2220。现以 `#else` 隔开两套互斥实现，不关闭 `/WX`。
- Visual Studio 多配置生成器不消费 `CMAKE_BUILD_TYPE`，构建脚本删除此无效参数，继续使用 `cmake --build ... --config Release`。

新增 `source/BloodStoneInput/tools/验证单DLL编译边界.py`，在没有 Windows SDK 时检查两个 `ResolveAutomaticControllerFamily` 条件分支的花括号、专版日志分支，以及三组 SDK 声明的语法；Linux 可移植 CTest 8/8 通过、原有图标 harness 5/5 通过。完整 Windows 链接与游戏运行仍未验证。此次修复不调整 JoyShim 输入策略、Stadia 身份识别、图标映射、D3D9 Reset、同名清空日志或命令行图标覆盖机制。

## Win32 第二轮实编反馈与入口修复

2026-10-28 的后续 Windows MSVC Win32 实编显示：CMake 配置通过，SDL3 3.4.18 的 `SDL3-static.lib` 构建成功，JoyShimCore 的 `JoyShimCore.lib` 也已构建成功。仅 `BondIconCore` 在 `BondGamepadIcons.cpp` 文件末尾报告 C2059/C2143/C2447（原日志行 6935/6937）。这与第一轮的自动识别函数缺失闭合花括号不是同一处错误。

真正的问题是专版 `BondIconsProcessAttach`、`BondIconsProcessDetach` 与独立 ASI 的 `DllMain` 共用一段条件编译和嵌套花括号；当 `BSCN_SINGLE_DLL` 生效时，原末尾多出一枚 `}`，导致外部 C 接口在错误作用域下解析。

当前实现将公共初始化逻辑抽出为 `InitializeBondIconRuntime`，再分别声明专版的两个 C 入口与独立版的 `DllMain`。专版仍由 JoyShim 的唯一 DLL 入口统一管理日志，图标模块不增加独立 DLL 入口；独立 ASI 的原有初始化、日志与退出清理语义保持不变。

为防止只检查自动识别函数、遗漏其他条件编译出口，`tools/验证单DLL编译边界.py` 增加了从实际源文件提取的入口代码 C++17 双模式严格语法检查。`build.bat` 在构建完整 `JoyShimDInput8` 之前先单独编译 `BondIconCore`，便于尽早发现图标语法问题，避免在错误时反复编译整个 SDL3。

本轮在非 Windows 环境执行：JoyShim 可移植 CTest 8/8 通过、五组图标回归 harness 通过、三组 XInput SDK 头桩检查以及独立 ASI/单 DLL 两套入口语法检查通过。尚未取得修改后完整 Win32 DLL 的实际链接及游戏运行结果，状态仍为待实编候选。
